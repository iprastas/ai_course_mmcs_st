# Городская справочная Ростова — веб-MVP (усложнение задания 1)

Работающее веб-приложение вокруг агента из задания 1: форма вопросов на сайте,
SSE-поток «как агент думает», учёт контекста диалога, вход пользователей,
многопользовательский async-бэкенд на **Python/ADK** и семантический поиск
через векторную базу (юзкейс: забыл название → ввёл «пельмени» → агент находит
рестораны по смыслу).

## Быстрый старт (чистая машина)

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```bash
uv sync                                    # зависимости (в т.ч. google-adk)
cp .env.example .env                       # вписать OPENAI_API_KEY, MODEL; APP_USERS — входы
uv run python week2/app/semantic.py --build  # построить векторный индекс (~1 мин, копейки)
uv run python -m uvicorn week2.app.main:app --port 8000
```

Открыть `http://127.0.0.1:8000`, войти (по умолчанию `admin:admin`, см.
`APP_USERS` в `.env`) и задать вопрос. Два окна под разными логинами работают
параллельно.

Проверка юзкейса без браузера:

```bash
uv run python week2/app/semantic.py --test пельмени   # прямой поиск по индексу
uv run pytest                                        # 25 тестов, без API модели
```

## Что делать на сайте

1. **Форма вопроса** (слева) — Enter отправляет, Shift+Enter перенос строки.
2. **«Как думает агент»** (справа) — SSE-лента в реальном времени: мысли модели
   → вызов инструмента с аргументами → результат → финальный ответ;
   карточки вызовов/результатов раскрываются по клику.
3. **«Контекст диалога»** — история вопросов/ответов текущей сессии; после F5
   восстанавливается из `/api/history`. «Новый диалог» сбрасывает контекст.
4. **«Найти по смыслу»** — мгновенный векторный поиск мимо агента
   (косинусный топ по индексу, вкладка со сходством в %).
5. В шапке — кто залогинен, счётчик шагов/токенов/₽ последнего прогона.

## Архитектурные решения (и почему именно так)

1. **ADK как фреймворк, свои инструменты как доменный слой.** Задание 1
   требовало цикл без фреймворка — он написан в `week2/assignment/agent.py`.
   MVP использует Google ADK (`LlmAgent` + `Runner`): сессии, события, лимиты
   даёт фреймворк. Пять инструментов переиспользуются из `tools.py` задания
   (описания full-варианта подставляются в докстроки — ADK читает именно их).
2. **LiteLlm поверх нашего провайдера.** Та же модель и ключ, что во всём
   курсе (`MODEL`, `OPENAI_BASE_URL` в `.env`) — переключение модели одной
   переменной, без привязки к Google API.
3. **SSE, а не WebSocket.** Нужен односторонний поток «сервер → браузер» на
   время ответа: проще, есть автопереподключение, не нужны handshake и
   штатные прокси.
4. **Контекст = ADK-сессия.** `InMemorySessionService` хранит историю диалога;
   на пользователя — своя сессия (многопользовательность из коробки).
5. **sqlite-vec для векторов.** Одна файловая SQLite-база, как `poi.sqlite`:
   без сервера и тяжёлых зависимостей; векторы L2-нормализованы, поэтому
   обычное расстояние vec0 = 1 − косинус.
6. **Эмбеддинги через AITunnel** (`text-embedding-3-small`, dim 1536): не
   качаем полгигабайтные модели, тот же ключ и `.env`; индекс — один скрипт.
7. **Авторизация своего слоя поверх ADK** (ADK не умеет пользовательский вход
   для своего UI): пары в `APP_USERS`, токен в HttpOnly-куке, мидлвар даёт
   401 для всех `/api/*`.
8. **Статика без сборки** (vanilla HTML/CSS/JS): запуск — только `uv`, на
   машине преподавателя не нужен node/npm.

## Структура

```
week2/app/
├── main.py        FastAPI: роуты, куки, SSE, статика
├── agent.py       ADK-агент + LiteLlm + маппинг событий → SSE
├── semantic.py    индекс sqlite-vec (--build) + инструмент semantic_search
├── auth.py        вход из .env
├── static/        index.html, app.js, style.css
└── vectors.sqlite индекс (40 МБ, в git не попадает — строится скриптом)
```

События SSE: `start → thinking* → tool_call → tool_result* → final → usage`
(+ `error` при сбое). Формат — в `week2/assignment/report.md` не нужен, см.
`main.py` / `agent.py`.

## Ограничения MVP (осознанные)

- история и токены входа живут в памяти процесса: рестарт = чистый лист;
- нет rate-limit и HTTPS (для локального демо);
- `max_llm_calls=12` — предохранитель от петли (ADK `RunConfig`);
- индекс строится вручную, не пересобирается автоматически при правке базы.
