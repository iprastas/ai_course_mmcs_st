# Городская справочная Ростова — веб-MVP (усложнение задания 1)

Работающее веб-приложение вокруг агента из задания 1: форма вопросов на сайте,
SSE-поток «как агент думает» (с таймингом и бейджами multi-agent), **несколько
диалогов** с контекстом каждого, вход пользователей, многопользовательский
async-бэкенд на **Python/ADK** (иерархия coordinator → researcher, очередь
прогонов), семантический поиск через векторную базу, **карта найденных мест**
и страница метрик задания.

## Быстрый старт (чистая машина)

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). Из корня репозитория:

```bash
uv sync                                      # зависимости (google-adk, sqlite-vec…)
cp .env.example .env                         # вписать OPENAI_API_KEY, MODEL; APP_USERS — входы
uv run python week2/app/semantic.py --build  # векторный индекс (~1 мин, копейки)
uv run python -m uvicorn week2.app.main:app --port 8000
```

Открыть `http://127.0.0.1:8000`. Учётки хранятся в SQLite (хэшем, не в `.env`):
**регистрация — кнопкой на экране входа**; стартовые пары `admin:admin`,
`guest:guest` зашиваются в базу один раз из `APP_USERS` (после этого пароли
из `.env` можно удалить). Или кнопкой **«Демо-вход»**, если заданы
`DEMO_USER`/`DEMO_PASSWORD`. Два окна под разными логинами работают
параллельно.

Прочее:

```bash
uv run pytest                              # 65 тестов, без API модели
uv run python week2/app/semantic.py --test пельмени   # проверка поиска из консоли
```

## Что умеет сайт

1. **Сайдбар диалогов** (слева): «+ Новый чат», список с названиями
   (название генерируется из первого вопроса: LLM-короткий смысл, запасной
   вариант — сам вопрос; ✎ переименовать, 🗑 удалить — в **модальных окнах
   приложения**, не в браузерных prompt/confirm); у каждого чата своя
   ADK-сессия и свой контекст; переключение — мгновенное. Чат создаётся
   лениво: пустых «Новых чатов» в списке не бывает, удаление — честное
   (сессия удаляется из ADK с проверкой, история хранится до явного удаления).
2. **Форма вопроса**: Enter — отправить, Shift+Enter — перенос; черновик
   переживает F5 (localStorage); во время генерации кнопка становится
   **«■ Стоп»** (прерывает прогон).
3. **«Как думает агент»** (справа) — SSE-лента в реальном времени:
   мысли с бейджем агента (🎯 coordinator / 🔬 researcher), строка
   **⇄ делегирования** при transfer, вызовы инструментов с аргументами
   и результаты; лента всегда **полностью развёрнута** — ничего не
   сворачивается и не прячется за клики.
4. **Follow-up чипы** «↳ продолжить:» под формой — 3 вопроса-продолжения
   после каждого ответа (один дешёвый LLM-вызов мимо агентского цикла).
5. **«📍 Запрошенные места»** — карта (Leaflet) с переключателем слоёв:
   **Улицы** (открытые тайлы OpenStreetMap — работают в России без ключей и
   водяных знаков; при недоступности CDN — авто-переход на зеркало
   `openstreetmap.de`), **Спутник** (бесплатные тайлы Esri World Imagery),
   **Топо** (OpenTopoMap). Пинятся только **релевантные** места: открытые
   агентом (details/nearest/find_places) и явно им отмеченные (`pin_places`);
   сырые кандидаты semantic_search (парфюмерия, цветы и прочий шум мимо
   запроса) на карту не попадают — карта не противоречит ответу. После F5
   карта восстанавливается из истории чата.
6. **Ответы-таблицы** — свой рендерер markdown: списки, жирный, код и
   **настоящие `<table>`**; на пузыре — кнопка **⧉ копирования**.
7. **«🔍 Найти по смыслу»** — мгновенный векторный поиск мимо агента
   (юзкейс: «пельмени» → Пельмень, Пельмешка, сходство в %).
8. **«📊 Метрики»** (`/stats`) — pass@1 / pass^3 / A/B / Вильсон прямо из
   журналов `week2/assignment/runs`.
9. **⤓ Экспорт** диалога в Markdown, **тема ☀️/🌙**, фавикон, адаптив.
10. В шапке — счётчик последнего прогона: шаги, токены, рубли, секунды.

## Архитектурные решения (для ответа преподавателю)

```mermaid
flowchart LR
  B[Браузер<br/>vanilla HTML/JS] -- form + fetch SSE --> F[FastAPI<br/>main.py]
  F -- cookie auth --> A[(auth.sqlite<br/>users/PBKDF2, tokens, chat_meta)]
  F -- user-lock + семафор 4 --> Q[очередь прогонов]
  Q -- SSE --> R[ADK Runner<br/>agent.py]
  R -- transfer --> C((coordinator))
  C --> W((researcher))
  W -- LiteLlm --> M[Модель<br/>через OPENAI_BASE_URL]
  W -- tools --> T[tools.py<br/>5 инструментов + semantic_search + pin_places]
  T --> V[(vectors.sqlite<br/>LRU-кеш эмбеддингов)]
  T --> P[(poi.sqlite<br/>8860 мест)]
  R -- сессии --> DB[(sessions.db<br/>WAL)]
  R -- JSONL --> J[runs/web_*.jsonl]
  F -- /stats --> S[stats.py<br/>pass@1, A/B]
```

1. **Multi-agent иерархия, а не один промпт.** ADK `LlmAgent(sub_agents=…)`:
   **coordinator** (корень, без тулов — делегирует и формулирует финал) →
   **researcher** (все 7 инструментов — только собирает факты). Разделение
   ответственности: исследователь не сочиняет, координатор не лезет в базу.
   **Модерация темы — жёсткий рубеж до прогонов** (`agent.check_topic`):
   вопрос мимо городской справочной («напиши калькулятор», «какая столица
   Франции») отсекается словарём явных сигналов (мгновенно и бесплатно) или
   одним дешёвым LLM-вызовом ДА/НЕТ (`reasoning_effort=low`) — пользователь
   получает вежливый отказ, агент и инструменты не запускаются, чат не
   создаётся. Инструкция координатора — лишь последний рубеж.
   Transfer ловится по `ev.actions.transfer_to_agent` и показывается в SSE
   строкой «⇄ coordinator → researcher». `max_llm_calls=16` — transfer ест
   вызовы. Пять инструментов переиспользуются из `tools.py` задания
   (описания full-варианта подставляются в докстроки — ADK читает их).
   Sync-тулы идут в thread pool (`tool_thread_pool_config`), а не в
   event loop — параллельные пользователи не ждут чужие sqlite-запросы.
2. **Очередь прогонов вместо отказов.** Глобальный `asyncio.Semaphore(4)`:
   слот = живой LLM-запрос. При заполнении пятый пользователь первым
   событием видит `wait` («в очереди»), а не тишину; время ожидания
   уходит в журнал (`queue_seconds`), активные слоты — в `/api/health`.
3. **LiteLlm поверх нашего провайдера.** Та же модель и ключ, что во всём
   курсе (`MODEL`, `OPENAI_BASE_URL` в `.env`); ретрай 2 раза, timeout 60 с,
   temperature 0.2.
4. **SSE, а не WebSocket.** Односторонний поток «сервер → браузер»:
   проще, есть автопереподключение. Сервер шлёт `: ping` каждые 15 с
   (прокси/таймауты); пинг не отменяет прогон — события агента итерируются
   в отдельной Task с очередью, таймаут лишь вставляет комментарий.
5. **Контекст = ADK-сессия в SQLite** (`DatabaseSessionService` + маппинг
   `login→session` и `chat_meta` в `data/auth.sqlite`): память диалога и
   вход переживают рестарт; у каждого чата — своя сессия. В каждый прогон
   модель получает только хвост истории — последние
   `MAX_CONTEXT_EVENTS=40` событий (`RunConfig.get_session_config`,
   ADK сам делает `ORDER BY timestamp DESC LIMIT n` в БД); UI читает
   сессию без лимита — после F5 виден весь диалог.
6. **sqlite-vec для векторов.** Одна файловая SQLite-база; векторы
   L2-нормализованы, поэтому расстояние vec0 = 1 − косинус. Индекс
   строится скриптом, при старте сервер пересобирает его в фоне, если
   изменилась `poi.sqlite` (сборка атомарная). Модель/размерность пишутся
   в `meta` и сверяются при запросе — смена `EMBED_MODEL` без пересборки
   даёт явную ошибку. Порог `MIN_SCORE=0.25` отсекает случайные совпадения.
7. **Эмбеддинги через AITunnel** (`text-embedding-3-small`, dim 1536):
   `AsyncOpenAI` — тул и `GET /api/search` не блокируют event loop;
   **LRU-кеш на 512 запросов** — повторные фразы (дебаунс, второй юзер)
   не идут в API (попадания видны в `/api/health`).
8. **Авторизация и учётные данные**: пароли не лежат в `.env` — учётки в
   SQLite (`users`, PBKDF2-HMAC-SHA256, соль на пользователя), регистрация
   на сайте (`POST /api/register`), вход — токен в HttpOnly-куке, 401 для
   всех `/api/*`; токены живут 12 ч в SQLite (обе базы — WAL + busy_timeout).
   `APP_USERS` в `.env` — лишь стартовый «бутстрап»: пары один раз
   зашиваются в базу хэшем, после чего `.env` можно почистить. На
   `/login` и `/api/register` — rate-limit 10 попыток/мин на «ip:login».
   **Демо-вход** одной кнопкой: `DEMO_USER`/`DEMO_PASSWORD` в `.env`.
9. **Статика без сборки** (vanilla HTML/CSS/JS): запуск — только `uv`,
   на машине преподавателя не нужен node/npm.
10. **Наблюдаемость:** каждый прогон — строка в `runs/web_*.jsonl`
    (вопрос, вызовы, transfer, точки карты, токены, цена, `queue_seconds`;
    статус `cancelled` при обрыве, `error` при сбое); `/stats` читает
    журналы задания; `GET /api/health` — индекс, семафор, кеш.

**Многопользовательский режим.** На пользователя — `asyncio.Lock`:
второй параллельный `/api/ask` получает 409, а не гонку в ADK-сессии.
Лок снимается только после `aclose()` потока (агент успевает дожурналить)
через обёртку `StreamingResponse` — обрыв соединения не «утечёт».

## Структура

```
week2/app/
├── main.py        FastAPI: роуты, куки, семафор, SSE, мультичаты, followups
├── agent.py       иерархия coordinator→researcher + LiteLlm + события→SSE
├── semantic.py    индекс sqlite-vec + semantic_search + LRU-кеш + авто-пересборка
├── auth.py        пользователи (PBKDF2-хэши), токены, chat_meta в SQLite (data/)
├── stats.py       метрики задания из runs/*.jsonl для /api/metrics
├── static/        index.html, app.js, style.css, stats.html, favicon.svg
├── vectors.sqlite векторный индекс (40 МБ, в git не попадает)
├── data/          auth.sqlite + sessions.db (в git не попадает)
└── runs/          журналы прогонов веба (в git не попадает)
```

События SSE: `start → wait? → thinking* → delegate? → tool_call →
tool_result → map_points* → answer_delta* → final → title? → usage`
(+ `error` при сбое); комментарии `: ping` каждые 15 с — heartbeat.
События агентов несут поле `agent` (координатор/исследователь).

## Ограничения MVP (осознанные)

- нет HTTPS (для локального демо) — rate-limit и SameSite=Lax уже есть;
- `max_llm_calls=16` — предохранитель от петли (с учётом transfer);
- лента мыслей агрегируется кусками ≥160 символов, ответ — ≥64;
- карта: у части мест из OSM координаты есть всегда, адреса — не всегда;
- `APP_USERS` — стартовый бутстрап открытым текстом (зашивается в базу
  хэшем при первом обращении; для продакшена оставить пустым и
  регистрировать пользователей на сайте);
- follow-up чипы — отдельный дешёвый вызов после ответа (при сбое
  просто не показываются, прогон не портят).
